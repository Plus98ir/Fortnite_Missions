Fortnite STW Missions Telegram Bot

A bilingual (English / Persian) Telegram bot that tracks Fortnite Save the World mission alerts: V-Bucks missions, Power 160 missions, Ventures 140 missions, the weekly Supercharger reward, and season countdowns. One command installs it as a hardened systemd service.

Open @plus98vbucks_bot Install on your server

No server? Use the public bot — I can’t promise how long it will stay online.

🚀 Install

  1. Get a bot token

    1. Open Telegram and search for @BotFather.
    2. Send /newbot.
    3. Pick a display name, then a unique username ending in bot (e.g. FortniteAlertsBot).
    4. Copy the HTTP API token BotFather gives you.
    5. Get your numeric chat ID from @userinfobot — that is the admin ID.

    ⚠️ Warning: keep your bot token private. Never commit it to GitHub or paste it into a chat. The installer stores it in a root-only file, never in the source code.

  2. Run the installer

    On a fresh Debian or Ubuntu server, as root:

    bash <(curl -fsSL https://github.com/Plus98ir/Fortnite_Missions/releases/latest/download/install_fortnite_bot.sh)

    Use bash <(curl ...), not curl ... | bash. The installer asks interactive questions and piping would swallow your answers.

    Or download it first if you prefer to read the script before running it:

    curl -fsSLO https://github.com/Plus98ir/Fortnite_Missions/releases/latest/download/install_fortnite_bot.sh
sudo bash install_fortnite_bot.sh

  3. Answer three questions

    • your bot token (validated before use, never echoed to the screen);
    • your numeric admin chat ID;
    • whether you need a proxy — and if so its type, host, port and credentials.

    Before starting the service it tests the connection both directly and through the proxy, then tells you which one works. Re-running the installer later upgrades the code and keeps your existing configuration.

🌐 Proxy configuration

You no longer edit any Python file. The proxy is a question during install, and can be changed at any time with fnbot config.

Note: a proxy is only needed if the server itself cannot reach api.telegram.org — typically an Iranian server. A VPS outside a filtered country needs no proxy at all. If you enter 127.0.0.1, remember it means the server’s own localhost, not your PC.

SOCKS5 proxies are automatically upgraded to socks5h for scraping, so DNS is resolved through the proxy rather than leaking to the local resolver.

After editing, run fnbot restart — or just use fnbot config, which restarts for you.

👑 Admin panel

Only the configured admin ID sees the 👑 Admin button.

  • Stats — total users, subscribers, banned, how many use filters.
  • Broadcast — press the button then send your message, or use /broadcast your text. Either way you get a preview with confirm/cancel before anything is sent. /cancel aborts.
  • Export — /export sends a CSV of every user with their language, alert setting, ban state and filters.
  • Import — send that CSV (or an old users.json) back to the bot to restore. Existing users are updated, new ones added, nobody is deleted.
  • Ban — /ban ID, /unban ID, /banned. Banned users are silently ignored and receive no alerts.
  • Refresh — /refresh clears the cache and forces a re-fetch.

⚡ Caching

Mission data changes only at the in-game reset, so the cache is valid until the next reset rather than for a fixed number of minutes:

DataValid untilSurvives restart
Missions (V-Bucks / 160 / Ventures)next 00:00 UTCyes
Weekly rewardnext Thursday resetyes
Season end datedailyno

For 20 minutes after a reset the cache refreshes more eagerly, in case the upstream source has not published the new data yet. If a refresh fails, the previous value is served instead of an error.

🔐 Security

  • The bot runs as the unprivileged fnbot system user, never as root.
  • Secrets live in a 0640 file, not in the source or the systemd unit.
  • Proxy passwords are redacted from every log line.
  • The systemd unit is sandboxed: ProtectSystem=strict, NoNewPrivileges, an empty capability set and a syscall filter.
  • Dependencies are installed in a virtualenv, leaving the system Python untouched.
  • All scraped text is HTML-escaped before being sent to Telegram.

🆕 What changed in v2

If you are coming from the first release, here is what is different.

Security
  • The token is no longer injected into the Python source with sed; it is read from an environment file.
  • The proxy password is no longer written into the world-readable systemd unit, nor printed to the terminal or the logs.
  • The service dropped from root to a dedicated user with a sandboxed unit.
  • pip --break-system-packages replaced by a virtualenv.
  • Proxy credentials are URL-encoded, so special characters no longer break the connection.
Bug fixes
  • HTTP requests had no timeout and could hang forever — now bounded, with retries and backoff.
  • The mission source is parsed as raw JSON or as JSON embedded in the page, instead of only the latter.
  • PySocks was missing, so SOCKS proxies never worked for scraping.
  • Markdown formatting broke whenever a mission name contained * or _ — switched to escaped HTML.
  • The weekly job used a day index that means different things in different python-telegram-bot versions; the weekday is now checked in code.
  • Blocking requests inside async handlers froze the event loop — moved to worker threads.
  • users.json was written non-atomically and could be corrupted.
  • Broadcasts had no rate limiting and could hit Telegram’s flood limit.
  • The Ventures cycle calculation was wrong across the new year.
  • Messages longer than 4096 characters were silently dropped — they are now split.
  • Works with python-telegram-bot 20, 21 and 22 (the Defaults API changed in 22).
  • A network failure at startup no longer crashes the service into a restart loop.
  • The Battle Pass timer falls back to the configured date when the live lookup fails.
New
  • Ventures 140 missions, dungeons excluded.
  • Per-user zone / reward / minimum-V-Bucks filters.
  • Alerts on-off toggle for every user.
  • Full admin panel: broadcast with preview, ban, export, import, refresh.
  • Reset-aware caching, persisted to disk.
  • fnbot management command.
  • Connectivity self-test during installation.

⬆️ Upgrading from v1

Just run the installer. It disables the old vbucksbot.service, copies /root/fortnite_bot/users.json to the new location, and migrates the old schedule settings. Nothing is deleted — the old directory stays where it is until you remove it yourself.

🩺 Troubleshooting

Start with:

fnbot errors
fnbot test
httpx.ConnectError: All connection attempts failed

The server cannot reach Telegram. If you set a proxy, nothing is listening on that address — check with ss -ltnp | grep PORT. Often the fix is to remove the proxy entirely.

401 Unauthorized

Wrong or revoked token. Get a fresh one from BotFather.

Mission lists are empty

The upstream site changed its format, or you are inside the 20-minute window right after a reset. Try /refresh.

Ventures list is empty

The zone name did not match the Ventures pattern. Check fnbot logs.

📝 Notes

  • The default cap is 200 users; change MAX_USERS in the config.
  • Mission data comes from third-party community sites. If one changes its layout, the bot serves the last known data and logs a warning.
  • Update SEASON_START_UTC and SEASON_END_UTC once per season so the Battle Pass progress bar stays accurate.
